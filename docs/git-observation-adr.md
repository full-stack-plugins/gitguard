# ADR: first Git observation slice

- Runtime tested: Rust/Cargo 1.90.0 and 1.99.0 on Linux x86_64, actual pinned `/usr/bin/git` 2.47.3. Edition 2024, declared Rust floor 1.90 validated by a full locked offline suite with the official isolated 1.90.0 toolchain. No cross-platform or untested Git-version minimum claim. Earlier 2.52.0 note did not describe the pinned executable and is corrected. Direct dependencies are exact-pinned and transitive versions recorded in Cargo.lock.
- Executable: `/usr/bin/git` only. Crate-owned argv only; no public arbitrary Git command runner. Environment is cleared and rebuilt without credentials. Private metadata contains only freshly initialized configuration and copied objects/index; source configs, refs, hooks, alternates and helpers are not used. Symlink metadata roots/object storage and alternate object stores fail closed. Linked worktree `commondir` is supported.
- Supported object algorithms: SHA-1 and SHA-256, each exercised with a real repository. Unknown object formats rejected. Immutable full lowercase OIDs only; origin URLs are not identities. `fsck --full --strict` checks object hashes before use.
- Limits: each subprocess has a 10-second timeout and 8 MiB per output stream by default. Object/worktree storage budgets are 64 MiB with a 100,000-entry traversal cap. Git runs in a separate process group killed on completion/timeout; output threads are bounded. Public Limits permit smaller caller budgets. No OS address-space/CPU quota or external sandbox is claimed.
- Git merge capability is tested through actual merge-tree/commit-tree execution. Only two-parent merges supported. Fixed preview identity/time make temporary commits reproducible. No rebase/squash, source writes, remote fetch, authentication, or platform event adapter.
- Paths: byte arrays, exact case, rename endpoints independently checked; no Unicode normalization. Symlink target bytes observed without recursion. Submodule content remains missing, never presumed complete.
- Snapshot and graph versions are local domain versions, not new GuardEngine envelope capabilities. Protected baseline source registration, authority and production graph provider remain unimplemented. Non-null baselines rejected rather than accepting a digest as authority.

Known hardening limits before untrusted production deployment: repository/worktree filesystem traversal is not a dirfd capability walk, so concurrent directory-replacement races are not fully contained; whole-process memory/CPU and descendant-process exhaustion tests remain outstanding; only the current Linux/Git toolchain has been exercised. Discovery copies a bounded repository view, but no atomic snapshot of a concurrently changing worktree is guaranteed. These limits prevent claiming full task 1.2 or authoritative clean admission. Callers should use controlled frozen local checkouts and revalidate at consumption. No writer is provided by this crate.


Discovery configuration capability (task1.1): freeze at most64KiB of the source config, parse using pinned Git's explicit `config --file ... --no-includes --null --list` in private metadata, and use section-qualified repositoryformatversion/objectformat. No source config is loaded as the operational Git configuration. Native quoting/comment/escape semantics apply. Includes/conditional includes, unknown extensions, duplicate format/version keys, explicit external core.worktree, bare worktree roots and unsupported algorithms/versions fail closed. Supported repository versions0/1; explicit objectformat requires1; absent format meansSHA1. Currently canonical version0/1 and bare=false values are required; alternative boolean/numeric spellings are intentionally unsupported. Remote URLs and unrelated sections do not select identity/algorithm. Source refs/index/files remain unchanged. `Repository::git_version()` exposes the actually invoked version, and `repo_id()` exposes only the caller's local label.

The fixed version matrix is a qualified local profile, not a promise that all future Git versions/extensions work. Every discovery actually initializes the selected object algorithm and fscks the copied object store; unavailable capabilities fail closed. Linked worktree common-dir, nonrepository roots, canonical root aliases, SHA1/SHA256, missing objects, source config injection/unknown formats and origin-independent labels have real Git fixtures. Source discovery still assumes controlled filesystem ancestry, as documented above; task1.2 hardening is distinct.
