# Bounded Git observation process profile

`gitguard.git-process/linux-single-v1` is a local Linux boundary for existing fixed `/usr/bin/git` commands. Linux x86_64 is actually tested; the architecture-specific aarch64 filter is implemented but not executed here. Other targets or unavailable kernel filtering fail with `UnsupportedProcessProfile`. This is not a general execution sandbox, hostile-host protection, executable attestation or production admission authority.

Callers never supply an executable, shell command or arbitrary Git argv. Existing methods assemble fixed argv and validate OIDs. Git runs in the private copied object store with a cleared environment and explicit no-includes source-config parsing. System/global config, helpers, attributes, hooks, replacement objects, lazy fetch, prompts and optional source locks are disabled or excluded. Actual diff commands disable external diff/textconv. Source object alternates and config includes are rejected. NUL raw-path parsing retains non-UTF8 and newline filenames.

After fork and before exec, async-signal-safe setrlimit/prctl install zero soft/hard core-dump limits, no_new_privs and prebuilt seccomp BPF. The filter checks audit architecture before syscall numbers; x86_64 also rejects the x32 number range. Forbidden fork/vfork/clone/clone3, socket/socketpair/connect and execveat attempts terminate the process. A supported invocation therefore has one process, no threads or descendants; there is no host-wide subreaper, wait-any-child or signal-handler change. SIGSYS is `ProcessPolicyDenied`, not success or a merge conflict. The initial trusted Git execve is allowed: this is not a hostile-code syscall whitelist or a replacement for trusted toolchain selection.

Git fsck normally launches commit-graph/multi-pack-index accelerator verifiers, even for small repositories. Private core.commitGraph=false and core.multiPackIndex=false prevent those optional helpers. `fsck --full --strict --no-reflogs` still verifies actual loose and packed objects, tested with real gc-packed storage. A Git command/version requiring forbidden syscalls fails rather than weakening the profile. Full tests cover existing candidate/merge-tree/commit-tree/index/tree/diff behavior.

Each invocation permits at most10 seconds and8MiB combined stdout+stderr, plus250ms direct-child termination/reaping budget. Callers can tighten but not expand maxima; copied object storage retains64MiB/entry limits. Nonblocking pipe reads share one byte budget, use bounded chunks and check deadlines every turn. Reader threads and unbounded joins are removed. Failure closes pipes, kills/reaps the sole child and returns a fixed diagnostic; failed cleanup is `ProcessCleanupFailed`. No raw stderr, URL, token or supplied path reaches diagnostics. Captured stderr is private and discarded; core dumps are prohibited. These are per-process/retained-byte bounds, not a total repository-scan deadline, exact RSS or guarantee against scheduler/kernel/uninterruptible-I/O delays.

Tests distinguish actual Git security/compatibility from fixed private process fixtures. Real malicious config/hook/diff/textconv/helper/remote inputs, alternate/include rejection, inherited environment poisoning and missing objects cannot execute a sentinel or mutate source refs/index/worktree; full source state is compared. Private Python fixtures prove fork/socket denial, x32 termination, combined-stream limits, prompt flood termination, timeout/reaping and disabled core dumps. No fixture executor is public. Initial helper-execution and unlimited-budget probes were behavioral RED; later safety tests are not all labelled historical RED.

Remaining assumptions: stable local source metadata and trusted parent directories. This slice does not repair every source-copy TOCTOU race, authenticate repository identity, implement Git writes/fetch, protect from hostile same-UID code, or qualify other platforms. Task1.2 remains unchecked pending independent review against its original criteria.
