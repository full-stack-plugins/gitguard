# ADR: optional Git executor remains disabled

The default Cargo feature set is empty. `privileged-execution` is a reserved opt-in capability gate, not an implemented writer. `execution::ExecutionConfig` defaults to enabled=false and denies unknown fields. A request for CreateWorktree, CreateBranch, Push or Merge returns Disabled unless both feature and config are set; even then it returns AuthorizationUnavailable because no reviewed external authorization provider exists.

No mutation transport, credential loader, signer, grant validator or external identity service is linked. This deliberately always-denied boundary is the supported behavior of task 4.1, not an emulated successful write. ALLOW, FlowGuard gate results, Markdown accepted, approved=true and authorizationReviewed=true cannot enable it; those extra configuration fields are rejected. Tests also produce a real engine ALLOW while source refs/index/worktree bytes remain unchanged and the merge port still rejects.

A future executor requires separate review of external issuer/actor/action/repo/exact candidate/expected target, immutable policy/approval binding, clock/expiry/revocation, credential scope, atomic target preconditions, durable intent and uncertain-write recovery before code can replace this denial. Read-only Git observation credentials must remain absent; any execution credential would come from that separately reviewed controller and never from a candidate/report Boolean. No provider, trust root, key storage or release authorization is selected here. Groups 4.2–4.5 are not implemented.
