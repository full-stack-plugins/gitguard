# Read-only operation grant validation

The opt-in library module `execution::grant` validates current controller-issued grant observations. It does **not** enable `execution::request`, create a writer/credential transport, change Git refs/index/worktrees, or grant execution permission. `GrantAction` has no conversion into executor `Operation`. Default and feature-enabled executor denial remains unchanged.

`OperationGrant` is strict versioned wire data. JSON decoding, an issuer string, a digest, or a candidate's approved/signatureVerified Boolean cannot authenticate it. An independently selected protected `GrantAuthority` must authenticate an opaque reference and return the current record, including revocation. A separate protected `GrantClock` supplies UTC Unix seconds. The controller owns both adapter implementations and IDs, policy and actor identity; self-reporting an adapter ID is not cryptographic authentication. There is no production provider/default trusted clock in this slice.

Before querying either port, `GrantExpectation::freeze` validates an actual CandidateSnapshot against its Repository and freezes its complete binding digest. This covers task/requirements/worktree/base/queue/members/source/policy/baseline/allowed paths, including current supported candidate limitations. Exact repo/candidate, actor/action/target/expected-target/operation ID and allowed issuer set also bind the expectation. The caller supplies a protected target observation. The validator does not read a remote target or prove it is unchanged; a future executor must independently revalidate and atomically compare-and-swap the expected target.

Create-worktree uses a portable relative path; branch/push/merge use literal refs/heads paths. No dot/dot-dot components, leading dot, lock suffix, controls, absolute paths, empty segments or URI targets. Create actions require expected absence (null), push/merge require an exact object ID with matching hash width. Each action is distinct: worktree/branch creation does not imply push/merge authority. No script/URI/path is executed by validation.

`GrantSession::validate` reads and advances a private monotone clock/generation, calls authority outside the lock, then re-reads the trusted clock even if authority failed. After reacquiring the lock it rejects rollback or any superseding attempt before validating returned fields/current validity. Failed expiry/provider results never rewind the watermark. A reentrant callback cannot deadlock the session; an older concurrent completion cannot publish success after a newer observation. Every retry queries the ports again. The opaque returned `GrantObservation` contains only identity hashes and observation/expiry time, not a consumable write capability. It is historical evidence, not a cached permission.

Limits: borrowed expectation/candidate/policy JSON <=1MiB before hash/copy, record and raw JSON <=16KiB, references <=2,048 bytes, actor/issuer/operation/adapter IDs <=128 bytes, repo/target <=256 bytes, <=128 issuers, lifetime <= a positive controller maximum capped at86,400 seconds. Grant interval is [not_before, expires_at); negative clocks, future not_before, exact expiry, revoked records and unavailable/untrusted ports fail. Malformed/oversized returned records are rejected before adapter-owned copy/hash. These limits do not claim to control upstream provider allocation or OS process memory.

Schema `schemas/operation-grant.schema.json` describes data shape; runtime additionally enforces UTF-8 byte caps, duplicate keys, exact nullable presence, cross-field interval/OID constraints, current authority and protected expectations. `fixtures/schema/operation-grant-valid.json` is explicitly unauthenticated fixture data.

This is a process-local session, not a durable nonce ledger or global clock. It does not consume an operation ID, select a production issuer, hold credentials, perform atomic Git admission or handle uncertain writes. Tasks4.3–4.5/platform enforcement remain separate. Tests use an explicit fixture-only issuer/clock and actual temporary Git candidate with source bytes checked before/after. No approval flags were added to the legacy execution config.
