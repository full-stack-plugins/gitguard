# ADR: local evidence consumption and process-local history

Status: implemented local profile, awaiting independent review. Candidate wire remains `gitguard.candidate/v1alpha2`; new reuse identity is `gitguard.reuse/v1alpha1`. This does not enable production authorization or writes.

`evidence::consume::consume` consumes the GitGuard check bundle through GuardEngine's actual artifact verification and eligibility ports. It validates the observed candidate, every envelope binding field, the full candidate scope digest, domain bytes/version and candidate identity. Unknown top-level domain fields are rejected. It does not consume arbitrary CodeGuard/FlowGuard domain profiles. The domain changes list is diagnostic, not authority; path semantics are produced by the GitGuard mapping and issuer trust still requires an external provider. Non-null baseline binding remains unsupported by candidate preparation.

Each consumption calls the supplied `AuthorityProvider` freshly at controller-provided time. Default `UnavailableAuthority` denies authenticity. Approval evidence cannot rewrite the report's REQUIRE_APPROVAL decision. Local test providers are fixtures only. A recomputed report, advisory boolean, process exit code, or user-supplied principal is not production authentication. The embedding trusted controller must supply policy, time, dependency/configuration digests and independently authenticated provider implementations.

`ReuseKey` hashes the complete candidate binding, complete GE eligibility policy digest, dependency digest and configuration digest. Policy includes expected producer/analyzer, source/baseline/contract, required coverage, action and authority requirements. Equality permits considering input reuse only; expiry and revocation still require fresh consumption. No cached-authority API is provided.

`LocalHistory` uses the actual GE `InMemoryAttemptStore` inside one shared `Arc<Mutex<_>>`. Registration compares the expected generation; completion appends immutable attempt records; publication requires the current generation. Tickets are tied to their store allocation, run, candidate and policy. Same-binding retries receive distinct run IDs and advance the generation. Late results remain history and cannot replace a newer attempt. Distinct task/requirement targets remain separate even on one repository. Poisoned lock errors fail closed.

This is process-local atomicity only: no restart recovery, multiprocess coordination, persistence, storage transaction or durable execution intent. `StorageRequirement::Durable` rejects immediately. `current` and `history` expose archival eligibility at observation time, not present authorization. Attempt registration, completion and audit append are separate operations; no transactional atomicity between these stores is claimed. Memory history has no general production retention/size guarantee. Task 4.4 is untouched.

`AuditLog` separately retains actual GE sanitized audit records, including hashed principal/cause metadata, at a caller-configured bounded capacity. Reading and expiry-based purging require an external `AuditIdentityProvider` and frozen reader/deleter allowlists. The default identity provider is unavailable. A full log rejects append rather than silently deleting records. Purging uses controller-provided time and removes only expired audit rows; it never mutates evidence/report/technical history. This is an in-process port, not a durable audit service, authenticated identity service or tamper-proof store.

Alternatives deferred: a persistent database and external service would require separate backend selection, crash/transaction tests, migration/retention policy and real authority-provider integration. No production dependency was added to simulate these guarantees. Protected admission and every executor operation remain denied.
