# Local freshness and audit

`FreshnessSession` adds a process-local observation API to the existing `ReuseKey`, `consume_bound`, and `AuditLog`. It is an opaque snapshot of controller-selected inputs, **not a permission, durable store, signed receipt, or cached eligibility**. No production authority provider is installed.

The protected controller calls `freeze` with the observed candidate, eligibility policy, dependency/configuration digests, complete typed `CheckBundle`, and time. `observe` accepts the current inputs again. The full reuse key includes the candidate's complete binding and full eligibility policy (including source/baseline, contract, analyzer, required coverage and principal policy), plus dependency/configuration identities. Changing these produces `InputsChanged`. Changing the serialized typed bundle, including run ID, approvals, artifacts or domain, produces `EvidenceChanged`. A retry/new run needs a new session. The digest covers the typed bundle's canonical JSON serialization; it does not authenticate its issuer or preserve discarded input whitespace.

Only equal identities reach the existing `consume_bound`: actual artifacts are verified/recomputed by GuardEngine and current producer/approval validity is queried again. `Rechecked` means evaluation ran; it does **not** imply eligible. Inspect `consumption().result()` and its unchanged GE decision/code. Missing attachments, expired/revoked records, unavailable providers, incomplete coverage and technical blocks cannot be repaired by the session. Invalid/admission-failed evidence produces no consumption and a static `InvalidEvidence` observation. Changing source inventory requires a newly observed candidate and current controller digests; this API does not independently watch external dependencies.

Time is protected-controller UTC seconds, nonnegative and monotonically nondecreasing per session/log. Equal timestamps are valid. An observation advances the session clock before fallible admission; a failed observation cannot reopen an older time. Clock/cause admission errors are static errors without an audit row. The controller must record those operational failures separately. No host clock authentication or cross-process monotonicity is claimed.

Borrowed JSON is counted before hash/serialization: policy <= 1 MiB, entire typed bundle <= 16 MiB, cause <= 16 KiB. Direct `consume` and `consume_bound` also retain these admission checks. Limits apply to adapter-owned serialization, not upstream allocations or an OS memory sandbox.

`AuditLog::append_freshness` accepts only the private observation. It records expected/observed identity hashes, static invalidation reason, hashed causal predecessor, timestamp and, when evaluated, the existing sanitized GE audit (hashed actors/purposes and GE reason). Raw inputs, provider error messages and causal secrets are omitted. Existing `append`/`read` APIs remain. `read_freshness` uses the same authenticated reader policy. There is one combined cap of 1..=10,000 rows; each admitted row is <= 4 KiB serialized, and reader/deleter configuration <= 64 KiB. Retention is positive and representable as signed seconds.

Authenticated deletion removes only expired local audit rows. Purge and append share a monotone clock, so an old row cannot be reinserted after advancing retention time. Unauthorized deletion cannot advance it. Neither retention nor read mutates original reports/history or changes eligibility. The controller must successfully append before treating an observation as audited; audit capacity failure is explicit. Storage is process-local and resets when the log is reconstructed. External authenticated identity providers and protected configuration/time remain deployment responsibilities.

Maintained tests: `cargo test --locked --offline --test freshness_audit`. The suite exercises each declared input dimension, exact bundle/missing-attachment/run changes, independent approval expiry/revocation, producer expiry/revocation, combined capacity, redaction, restricted retention, rollback and pre-serialization limits. Broader existing evidence/history/native tests remain unchanged.
