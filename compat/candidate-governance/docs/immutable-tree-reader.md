# Local immutable regular-file tree reader

`Repository::read_commit_files(full_commit_oid)` returns byte-path-sorted `CommitFile` entries with read-only `path`, `mode`, `object_oid`, and `contents` getters. It reads only the private object store created by Repository discovery, which already verifies actual object hashes using Git fsck. Later changes to source object files, HEAD, index or working-tree content do not change those private bytes. The read itself validates commit type and each blob type/size. Repository identity remains a caller-assigned local label, not authenticated ownership.

The method accepts only a full SHA-1/SHA-256 OID matching the actual repository format. It rejects symlinks, gitlinks and unsafe byte paths rather than following or omitting them. It preserves binary content, executable mode metadata and raw byte filenames. Consumers materializing files must impose their own supported path/mode semantics; ArchGuard uses a stricter UTF-8 regular-file subset. No files are checked out and no filters, attributes, hooks or remote helpers are invoked.

At most 10,000 files and the repository's cumulative storage byte limit are accepted. `ls-tree -r -l -z` supplies declared sizes; all entries are validated and charged before reading any blob, including the per-command output limit. Actual returned sizes must match. One wall-clock deadline covers type validation, listing and all blob reads; every call uses the existing reviewed process boundary. This avoids granting each of thousands of blobs a fresh timeout. The platform restrictions and fixed `/usr/bin/git` runner remain unchanged. The private object's earlier discovery/copy/fsck has its existing separate budget.

Real repository tests cover SHA-1/SHA-256 binary newline-named executable files, non-HEAD commits and dirty worktrees, unchanged source repository state, missing/noncommit OIDs, symlink/gitlink rejection, compressed oversized blob rejection, a single deadline over 1,000 entries, and a corrupted source object under another blob's OID. Fresh discovery rejects corruption while an already copied valid repository still reads original bytes. No grant, signature, admission, writer or additional task acceptance is introduced.
